Add an experimental sparse direct loop-closure solve to `SolverSteel`, selected with the kernel override `closure_direct_factor="sparse"` (off by default): each world factors the closure-augmented mass matrix `H + J^T W J` once per substep with a static-pattern supernodal Cholesky in shared memory instead of sweeping the closure rows serially. It supports one articulation per world with loop closures as the only constraint rows. A world whose factor meets a pivot that float32 cannot resolve (such as a scissor linkage at its flat, fully extended pose) is factored again with a small diagonal shift instead of returning NaN (`closure_direct_pivot_floor`, `closure_direct_pivot_shift`), and the solve sizes its shared memory from the device's per-block limit.
